## 🚀 How to Prevent This in Future

### ✅ DO:
1. Always use explicit migrations: `Add-Migration MigrationName`
2. Keep `AutomaticMigrationsEnabled = false`
3. Use consistent ContextKey: `C8.eServices.Mvc.DataAccessLayer.eServicesDbContext`
4. Review generated migration before running `Update-Database`
5. Commit migration files to Git immediately after creating them
6. Make migrations idempotent when necessary (check if columns exist)

### ❌ DON'T:
1. Don't enable automatic migrations in team/production projects
2. Don't mix SQL scripts with EF migrations for schema changes
3. Don't manually edit __MigrationHistory table without backup
4. Don't copy Model blobs between migrations
5. Don't delete migrations that have been applied in production
6. Don't change ContextKey after migrations are created

---

## 🎓 Lessons Learned

1. **Corrupted Model Blobs:** When Model blobs are copied/corrupted, delete and regenerate
2. **ContextKey Consistency:** Always use the same ContextKey for all migrations
3. **Automatic Migrations:** Great for prototypes, terrible for production
4. **Idempotent Migrations:** Use SQL checks when columns might exist
5. **Nuclear Option:** Sometimes starting fresh is faster than fixing corruption
